Pilares da POO

1. Herança

Mecanismo que permite que uma classe derive de outra, herdando suas propriedades e métodos. Promove reutilização de código e estabelece relacionamentos "é-um".

Exemplo: Cachorro extends Animal

2. Encapsulamento

Oculta detalhes internos de implementação e expõe apenas o necessário. Protege o estado interno do objeto e controla o acesso através de métodos públicos.

Exemplo: Propriedades private com métodos public

3. Polimorfismo

Permite que objetos de diferentes tipos sejam tratados de forma uniforme. O mesmo método pode ter comportamentos diferentes em classes diferentes.

Exemplo: animal.emitirSom() retorna 'Au au!' para Cachorro e 'Miau!' para Gato

4. Abstração

Representa conceitos complexos simplificando-os. Classes abstratas e interfaces definem o comportamento sem implementação detalhada.

Exemplo: abstract class FormaGeometrica define calcularArea() sem implementação

Boas Práticas em POO

✓ Princípio SOLID

Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion

✓ Composição sobre Herança

Preferir composição quando possível para evitar hierarquias complexas

✓ Imutabilidade

Preferir objetos imutáveis quando possível para evitar efeitos colaterais

✓ Injeção de Dependência

Injetar dependências em vez de criá-las dentro da classe
