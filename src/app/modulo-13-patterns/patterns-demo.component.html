2. Princípios SOLID Aplicados ao Angular

Clean Code
S - Single Responsibility:

Componentes devem cuidar exclusivamente de renderização e estado de tela; regras de negócio e chamadas HTTP pertencem aos Services.

O - Open / Closed Principle:

Entidades abertas para extensão e fechadas para modificação (ex: criação de novas diretivas e strategies sem alterar código existente).

L - Liskov Substitution Principle:

Subclasses ou implementações de interfaces (como nossos métodos de pagamento) podem ser usadas indistintamente pelo chamador.

I - Interface Segregation:

Criar interfaces pequenas e específicas ao invés de contratos gigantescos que obrigam implementações vazias.

D - Dependency Inversion Principle:

O coração do Angular: módulos de alto nível não criam instâncias, mas recebem abstrações injetadas via DI.

3. Estrutura de Pastas Recomendada (Clean Architecture)

Folder Architecture

Divisão canônica adotada por equipes enterprise em Angular moderno:

src/app/
├── core/             # Singletons, Guards globais, Interceptors HTTP, Auth
├── shared/           # Componentes reutilizáveis (botões, cards, modais), Pipes, Diretivas
├── features/         # Módulos de domínio da aplicação carregados via Lazy Loading
│   ├── dashboard/
│   ├── cursos/
│   └── checkout/
└── models/           # Interfaces TypeScript puras e tipos de domínio
